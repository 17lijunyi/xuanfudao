# Codex Float 模块

浮岛参考 MIT 项目 [CodexFloat](https://github.com/AI-Max2000/CodexFloat) 的额度与任务方案，将原音乐卡位改为 Codex 任务入口。横向首页与完整工作台共享同一份本机数据，音乐启动、播放、切歌和后台轮询均不在当前实现中；许可随安装包保留于 `THIRD_PARTY_NOTICES.md`。

## 折叠浮岛与预览

- 折叠态总宽 **256px**：中央 **200px** 物理刘海安全区加左右各 **28px** 侧翼。高度等于当前显示器菜单栏，下方两角使用 **17px** 半圆落脚。
- 左翼只显示白色 **13px** 剩余额度数字，不显示进度条；没有真实值时显示未知，不制造百分比。
- 右翼空闲时显示白色 Codex `>_`；真实任务运行时显示白色 **18px** 圆环，每 3.6 秒连续旋转；等待权限、等待输入、失败或中断时显示静态白色感叹号。刷新、排序或任务数量变化不会重启动画，减少动态效果时圆环保持静态。
- 悬停 **400ms** 后，岛体保持 256px 宽并展开为 **256 × 56px** 预览，显示最高优先级任务、状态和运行时长；移开 **250ms** 收回。点击、回车或空格直接打开完整工作台。

## 工作台与完成提醒

- 工作台任务按「需处理 / 运行中 / 最近完成」分组；等待权限、等待输入、失败和中断优先出现，详情最多显示八个任务。任务点击通过 `codex://threads/{id}` 进入本机 Codex，主进程只接受最新列表中存在的 UUID。
- 工作台左上「← 浮岛」会保存草稿、释放摄像头并返回 **1240 × 270px** 横向首页。横向首页按 Codex、番茄钟、日历、笔记、时钟和应用排列，让 AI 任务与当前专注状态优先出现。
- 完成提醒为纯黑色浮岛，与折叠态同宽 **256px**；菜单栏安全区下只增加 **28px** 内容。项目名以单行居中显示，右侧白色 Codex 图标约 900ms 转为中性灰底白勾，随后停留 **3 秒** 自动收回；悬停不延长。连续完成逐项排队，减少动态效果时直接显示勾。
- 按接口实际返回的额度窗口显示剩余百分比和重置倒计时，不凭空生成五小时或每周额度。额外 Reset 只展示次数、说明和到期时间，不提供兑换按钮。
- 无客户端、未登录或连接失败时显示明确状态。没有获取到的数据为未知；已有快照在离线时注明陈旧，不显示虚假的 0%。

## 实时任务与数据边界

浮岛通过本机 Codex CLI 的 App Server 建立标准输入输出连接，握手后只调用 `account/rateLimits/read` 和 `thread/list`。任务列表使用 `useStateDbOnly: true`，只采用现有 `name` 标题，不从聊天预览补标题。App Server 历史用于列表与显示信息，不能单独证明任务正在运行。

实时状态由官方生命周期 Hook/notify 提供，本机鉴权接收端最多同时追踪 **32** 个任务。已确认的长任务不会因五分钟没有工具活动、跨天或最近列表刷新而丢失；PermissionRequest 与 `request_user_input` 分别进入等待授权和等待输入，后续工具活动可恢复运行。Stop 只表示等待完成确认，`agent-turn-complete` 才确认成功；失败、中断、子代理、云端和旧历史不会冒充成功完成。重新连接时只按官方活动标记恢复，不把未知历史猜为运行中。

浮岛不直接读取 `auth.json`、聊天正文、rollout 文件或浏览器 Cookie，额度读取不修改 Codex 配置、不发送任务，也不消耗 Reset。任务 Hook 必须由用户在 Codex 正常审核入口确认和信任，详见[任务事件接入](codex-lifecycle-setup/README.md)。账号登录由本机 Codex 客户端管理；额度与任务模块本身不需要辅助功能或屏幕录制授权。

已确认的本机事件通过 `codex-activity-cache.js` 写入 `userData/codex-activities/`；目录权限为 0700，事件文件为 0600，按回合保留原始开始时间和最少显示元数据。Hook 先更新缓存再发送本机 HTTP，因此应用关闭期间的完成事件也能覆盖旧运行状态。冷启动只恢复原 PID 与启动时间都匹配的存活任务；不可确认的进程不会被猜成运行。初次恢复的终态不补弹通知，后续恢复的真实终态可结束已观测的任务。普通退出保留缓存，切走 Codex 清除缓存；最多保留 64 条有效记录，旧终态优先清理。

本机桌面版的 `PreToolUse` 实测不提供 `CODEX_THREAD_ID`，会话文件名采用 `rollout-时间-线程UUID_附加UUID.jsonl`。[官方 Hook 字段说明](https://learn.chatgpt.com/docs/hooks#common-input-fields)指出子代理的 `session_id` 可能沿用父会话，因此不能只依赖该字段。脚本优先核对线程环境变量，缺失时从事件已有的 `transcript_path` 文件名解析第一个 UUID 并要求完全匹配；子线程、冲突身份或未知文件名格式均不通过。这里仅解析已收到的路径字符串，不读取或保存会话文件及其内容。

参考项目的独立浮窗拖动、菜单栏形态和第三方 Tibo 公告／重置概率未移植；浮岛使用自己的贴顶窗口、任务预览和工作台。

## 验收

安装前检查动态额度解析、空值、离线保留、RPC 超时、任务跳转白名单、32 个任务的有界跟踪、长任务、等待用户处理、失败／中断投影、预览与两个工作台入口。安装后以 `/Applications/浮岛.app` 的实际版本、额度和真实任务事件为准，不能用测试样本截图代替账号数据验证。

系统音量与亮度按键接管属于浮岛窗口能力，需要用户另行授予 macOS 辅助功能权限，与 Codex 数据连接相互独立。打包与朋友分发遵守 [macOS 签名、公证与发布](releasing.md) 的 Developer ID 流程。

协议依据：[OpenAI App Server](https://learn.chatgpt.com/docs/app-server)。
