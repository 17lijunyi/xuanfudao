# 速览与工作台切换闪烁

2026-09-21，用户提供的 7.6 秒视频中，工作台和速览来回切换时，旧内容先消失，短暂出现空白玻璃或后方桌面，再出现新内容。

原路径把页面切换实现为两次独立的收起与展开：工作台先执行关闭动画并缩回 256px，再显示速览；速览进入工作台时则先隐藏速览，再等待工作台展开及内容绘制。这使两个窗口之间出现没有完整页面覆盖的时间段。

现在由 `window-handoff.js` 管理一次交接：保留旧窗口，目标窗口在不可见状态下准备完整布局和原生玻璃；真实渲染层通过 preload 确认准备完成，主进程刷新目标窗口自身的 Chromium 帧后再交接显示。帧图像仅在内存中短暂存在，不保存或传输，不采集桌面。预备页面临时关闭入场过渡，避免先画空壳再淡入文字。折叠岛的正常展开与主动收起仍沿用原动效。

交接按窗口身份和递增编号确认，处理超时、取消、快速连续导航、目标退出与迟到事件。交接过程中取消收起请求会停止预备窗口；只有最终交接中的焦点转移被忽略，用户正常切换到其他应用仍会收起。离开页面前保存草稿并释放镜子摄像头。

验证：

- `npm test` 通过：335 项 Node 单元测试、20 组 Electron 界面回归及脚本语法检查。
- 新的 `tests/window-handoff.electron.js` 使用真实主进程函数、preload、两处渲染页面和原生玻璃模块。验证 1040/1240 宽、柔焦玻璃/纯黑、旧页面保留到目标完整绘制、笔记草稿、连续导航、取消与 Esc。
- 用 `FUDAO_APP_ROOT=/Applications/悬浮岛.app/Contents/Resources/app` 对本机安装文件再跑同一交接测试，通过。
- 本机安装版正常退出后增量更新 7 个文件，重签并恢复自定义图标；权限配置保持一致。重启后实际操作速览进入工作台及返回速览，均完整显示。

本机更新保留安装版 `renderer/app.js` 中与本次修复无关的既有差异。备份及各项测试日志位于 `~/Library/Application Support/悬浮岛维护备份/20260921-window-handoff-133134/`。
