## 为什么需要这一连接

本机当前 Codex 会话的任务元信息会更新，但 `thread_history_1.sqlite` 的最后回合仍是旧的 interrupted。独立启动的 App Server 返回零个已加载任务，不能直接订阅另一个桌面进程中的全部活动。因此仅轮询额度和历史数据库，无法可靠知道用户此刻正在运行的任务。

## 事件与异常行为

- `UserPromptSubmit`：运行开始。普通 `PreToolUse`：活动心跳；当规范化后的工具名为 `request_user_input` 时，改为“等待输入”。工具事件必须带有与 `session_id` 一致的 `CODEX_THREAD_ID` 环境值，避免将子代理使用父会话 ID 的工具事件记到父任务。
- `PermissionRequest`：只记录“等待授权”，不读取或转发命令、参数、审批原因。`PostToolUse/request_user_input`：用户回答后恢复为运行。未识别的工具名不会被猜成等待状态。
- `Stop`：模型准备停下，并不保证回合真正完成，因为其他 Stop Hook 可以要求继续。因此只显示“正在确认完成”，不打勾、不发完成提醒；重复 Stop 也不会重复提醒。
- `notify/agent-turn-complete`：真正完成，必须同时带有效 `thread-id` 和 `turn-id`。缺回合 ID 时忽略，不猜测当前回合。
- `Interrupt`：中断；不映射成成功完成。不注册 `SubagentStop`。
- 元数据中来源不是本机交互会话、带父任务标记或云端标记的任务，不接受为可通知对象。新任务事件可以短暂等待只读列表校验，未经校验不展示其运行状态。
- 已确认的 Hook 运行与等待状态不再因长时间没有工具活动而过期，等待完成确认也保留同回合的提醒资格。可选 `ownerPid` 与 `ownerStartedAt` 必须成对：脚本只读取父进程链中的 Codex 进程号及启动标记；浮岛约每十秒检查同一进程是否还在，确认已退出或进程号复用时转未知并取消完成资格，读取失败则不推断退出。进程存活只能保留已有运行证据，不能据此产生新任务。旧脚本没有进程字段时仍兼容，等待明确完成／中断或服务重启清理。
- 当前 App Server 的 `thread.status.activeFlags` 是重启后的权威恢复来源：只把 `waitingOnApproval` 映射为等待授权、`waitingOnUserInput` 映射为等待输入；未知 flag 仍按普通运行处理。内存 Hook 状态在重启时清空，不从旧事件恢复。任务读取与生命周期记录均最多保留 32 条；同一线程／回合的重复事件和完成记录会去重。
- 重启浮岛不会恢复磁盘中的旧 running 状态；下一次真实开始或满足身份校验的工具事件才能恢复。已确认的活动任务元数据与最近八条展示列表分开保存，不因其他任务刷新挤出而丢失。已确认的完成或中断保留到新回合或更新的任务元信息。
- 额度连接失败不会清除已经鉴权、来源已核实的 Hook 活动或阻止其完成提醒；离线期间的旧数据库状态仍然不作为运行、完成依据。
- 只有本次监测观察过同一回合的运行再到完成，才发送完成提醒。启动时的历史完成、断线后迟到的旧历史、重复回调都不弹。

## HTTP 合同

`POST /codex-lifecycle`，必须带 `Authorization: Bearer <本机令牌>`。主进程限制请求体为小型 JSON，建议 4 KiB；不能记录令牌或原始请求。

```json
{
  "version": 1,
  "kind": "running",
  "threadId": "有效任务 UUID",
  "turnId": "有效回合 ID",
  "at": 1788466480000,
  "source": "local",
  "parentThreadId": null,
  "agentId": null
}
```

`kind` 仅允许 `running`、`attention`、`stopping`、`interrupted`、`completed`。`attention` 必须额外携带严格枚举的 `attentionKind: "permission" | "input"`；其他事件不得携带该字段。服务拒绝额外字段、无效身份、非本机/子代理标记、超过一分钟的旧事件和明显未来时间。`codexFloat.ingestTaskEvent(payload)` 返回 `{ok, error?}`，新任务尚待元数据时附 `pendingMetadata: true`。

1.4.6 可选字段 `ownerPid` 为正整数，`ownerStartedAt` 为规范化英文 `ps lstart` 启动标记（例如 `Fri Sep 4 13:34:24 2026`），仅用于已观察活动的源进程存活核验；二者必须同有或同无，不包含进程参数、聊天内容或登录数据。

状态快照中的 `runningTasks` 与 `attentionTasks` 最多各 32 项，用于保留真实并发数量；界面只显示一个持续圆环，并在详情中统一截取最高优先级的八项。运行项使用 `progressMode: "indeterminate"`，没有伪造完成百分比。`threads[].status = "attention"` 时，`attentionKind` 仅可能为 `permission` 或 `input`，对应 `statusReason` 为 `awaiting_permission` 或 `awaiting_user_input`。`recentCompletedTasks` 与 `recentIssueTasks` 按时间倒序、同一线程／回合去重，最多八项并保留五分钟。完成回调 `onTaskComplete` 仅含事件 ID、任务 ID、回合 ID、已有任务标题和完成时间。
